## 실제 장비에서 남는 사항

S1의 수신 경로 판단은 2026-11-09 팀 Android `895bb08` 확인으로 갱신했다. 기어·방향지시등은 Pleos Vehicle 2.3.2, 차속은 Android CarPropertyManager로 구현돼 있고 README에 팀의 에뮬레이터 확인 기록이 있다. 이번 검토에서 기기를 재실행한 것은 아니다. 남은 문제는 기어 재관측·원본 m/s·관측 시각·단절 처리와 정차 잠금의 연결이다. 현재 기어 조회는 시작 때 한 번이며 속도 heartbeat는 콜백 내부 전송 제한이어서 신선도 계약을 충족한다고 볼 수 없다. SDK 현재값 조회가 새 관측을 보장하는지도 확인해야 한다. 상세 충돌과 확인 항목은 `pleos_sdk.md` 2장에 기록했다.

S2의 `zone_id`·`intersection_id`는 SDK 제공 필드라고 가정하지 않는다. 앱이 검증된 지도·경로 대응으로 안정적인 ID를 만들고 모든 신호를 같은 단조시계로 표시해야 한다. 대응 자료가 없으면 관련 안내를 비활성화한다. `day_key`는 앱이 Asia/Seoul 날짜를 쓰도록 권장하며 엔진은 기존 opaque 키도 허용한다.

S3은 공식 Kotlin·Java 예제의 좌표 순서가 서로 달라 생기는 연결 위험이다. 고정 SDK 버전의 실제 생성자와 Kotlin 이름 붙은 인자, 지도상 위치·경로 결과를 함께 시험한다. 상세 공식 링크와 기능 차단표는 `pleos_sdk.md`에 있다.

## 실행·평가 변경점

- 모델은 `scripts/run.sh start/model` 또는 `start_model.ps1`로 시작한다. 실제 모델 프로세스의 `run/llama.pid`가 필요하며, 임의의 원격 모델 서버를 검증된 로컬 서버로 취급하지 않는다.
- 모델 파일·어댑터·런타임이 바뀌면 AI 서버도 재시작한다. 새 코드의 `/health/ready`가 200인지 확인한다. GGUF 해시는 첫 확인에 시간이 걸릴 수 있다.
- `test.locked.jsonl`은 바이트 그대로 보존한 퇴역 자료다. 새 `test.locked.v2.jsonl`은 44건이며 아직 draft다. `train/eval_boundaries.json`에 봉인·노출 내역을 기록했다.
- 개발 평가의 draft 자료 사용은 가능하지만, 최종 시험과 release_gate 합격은 자료 자체의 검수 완료를 요구한다. 정답을 검증기에 맞춰 바꾸거나 승인 표시를 자동으로 채우지 않는다.
- 로컬 해시와 시도 기록은 실수·혼합·반복 실행을 막는 장치다. 파일과 기록을 함께 고치는 악의적 변경까지 증명하는 전자서명·원격 증명은 아니다. 자동 통과율은 저장된 pass 값 대신 결과에서 다시 계산한다.
- 실제 Qwen 품질 평가, 파인튜닝, 원어민 검토, Pleos 기기 연동은 이번 코드 검사로 완료되지 않았다.

## 48e42e2 예약 인원수 회귀 후속

`para cinco/diez/veinte para las ...`는 숫자 바로 앞의 `para`를 수량 문맥으로 처리한다. 공통 판별식을 사용해 숫자 검증의 `count` 단위와 프롬프트 시각 힌트가 함께 교정되도록 했다. 세 예약 문장의 한↔스 정답·분전 오답·인원수를 분으로 바꾼 오답과 두 스페인어 locale의 정확한 힌트를 검사한다. `Salgo diez`, `Te veo cinco`, `Abrimos un cuarto` 등 기존 분전 표현의 검사는 유지한다.

다듬기와 관용적 대기 표현의 비차단 한계는 이번 패치에서 확장하지 않았다. 다듬기는 기본 꺼짐이며, 실제 모델·언어 검토와 SDK 기어·차속 연결은 별도 검증이 필요하다.

## 2026-11-09 번역 재시도 검토 후속

- 첫 요청에도 `target_language`로 Korean/English/Spanish를 명시한다. `translate-v8`은 1인칭 약속과 물건을 주고받는 사람을 유지하도록 지시한다. `nat-koes-003`의 역할 반전이 실제 모델에서 없어졌다는 뜻은 아니다.
- POI 이름·별칭과 `proper_name`으로 표시한 용어만 가린 뒤 영어/스페인어 기능어를 센다. `Pico del Amanecer de Seongsan`의 `de/del` 때문에 영어를 통과시키던 재현 사례를 차단하며 일반 명사와 부정어는 가리지 않는다. 등록되지 않은 이름과 짧은 문장의 언어 판정에는 한계가 있다.
- `no toma diésel, sino gasolina`의 연료 극성 검사를 수정했다. 반대 연료를 금지하는 오답은 계속 차단한다.
- 영어 `quarter past/to`, `half past`는 검증기와 같은 시각 파서를 사용해 한국어 힌트를 준다. `one by one`은 시각으로 읽지 않는다. 한국어 안의 `6 p.m.`는 `오후 6시`로 정규화한 다음 원문과 검사한다. 오전/오후가 서로 모순되면 재시도하고, 다듬기 결과의 모순은 유효한 초안을 유지한다. `number_missing`과 `number_added`가 함께 있으면 숫자를 추가하지 말라는 일반 지시 대신 원문과 구체적인 힌트로 잘못 읽은 값을 교정하도록 한다.
- `rental-ko-en-es-v10`에 `정산기 → payment machine / máquina de pago`를 추가했다. 용어집은 계속 검수 전 `draft`이며 `máquina de cierre`를 생성하지 않는지는 실제 모델로 다시 확인해야 한다.

## repair-v8 보고 후속: translate-v9

사용자 제공 보고에는 재시도 7건 중 `wrong_language` 0건, 검사 통과 회복 4건이 있다. 전체 실행 요약과 원본 로그가 로컬에 없어 첫 시도 전체의 언어 오류율과 두 시각 사례의 성공 여부는 재집계하지 않았다. 특히 `d-a-001`은 검사 통과 후에도 `free → 자유롭다` 오역이 남았으므로 4/7을 의미 정확도 회복률로 부르지 않는다.

- 용어집 `rental-ko-en-es-v11`에 `self_service`와 `full_service`를 추가했다. 외국어의 한국어 힌트는 `셀프 주유`·`직원 주유`다. 한국어 원문은 `셀프`로 매칭해 `셀프 주유소`의 `주유소` 힌트를 가리지 않는다. 이를 위해 self_service의 한국어 출력값만 `preferred`로 지정하고 기존 용어는 첫 별칭을 유지한다. 스페인어 힌트는 `autoservicio`와 `servicio completo`이며 연료 개념으로 등록하지 않는다.
- `translate-v9`에 평가·학습 자료와 지문이 겹치지 않는 선택 질문 예제 한 건을 추가했다. 원문에 부정 표지가 없는 영어 선택 질문에서 `negation_mismatch`가 난 경우에만 선택지를 부정으로 바꾸지 않도록 보강한다. 기존 부정 검사는 완화하지 않았다.
- 한국어의 `you`를 기계적으로 `당신`이라 쓰지 않되, 생략해도 지칭이 분명하거나 원문이 뒷받침하는 호칭을 사용하도록 지시한다. 역할·장소를 임의로 바꾸지 않는다.
- 검사기는 `mixed_script:anut`처럼 중복 제거한 영문 조각을 준다. 재시도는 해당 조각이 포함된 실제 원문 낱말(예: `peanuts`)을 찾아 온전한 한국어 낱말로 옮기도록 한다. 오답 초안은 다시 넣지 않으며, 원문에서 찾지 못하면 낱말을 추측하지 않고 일반 교정 지시를 유지한다.
- 평가 버전 `eval-ko-en-es-v5`는 `d-a-001`의 `must_include`에 `무료|공짜`를 추가한다. 원문·기존 reference·잠긴 시험·기존 결과는 바꾸지 않았다. 이전 자동 통과율과 비교할 때는 보존된 출력을 같은 기대값으로 재채점해야 하며, 새 기준을 이전 수치에 소급해 덮어쓰지 않는다.

이는 코드·검사 기준 보완이며 모델의 `free`, 선택 질문, 혼합 문자 오역이 실제로 해결됐다는 뜻은 아니다. 같은 개발셋으로 다시 실행하고 자동 통과와 의미·자연스러움 판정을 함께 확인해야 한다.

최종 로컬 검증: 전체 테스트 1,184건·주행 시나리오 통과(`run/verify-bb9c213e73/report.json`), 현재 코드·문구의 해시 일치 확인, 토큰 예산 932건 통과(최대 2,696/4,096토큰). 실제 모델 재평가는 수행하지 않았다.

## repair-v9 보고 후속: 미지원 언어와 목적지

사용자가 공유한 DLPC 집계는 dev 번역 73/75, general 157/160, general_es 90/90, naturalness.dev 20/20이며, 첫 시도 오언어는 기록된 343건 중 0건이다. 재시도는 15건에서 5건, 502는 4건에서 3건으로 줄었고 general_es p95는 498ms에서 343ms로 낮아졌다. 이는 사용자 제공 수치이며 원본 `run.json`·`results.jsonl`·시도 로그를 로컬에서 재집계한 결과가 아니다. 지연 집계는 HTTP 200 응답을 대상으로 하므로 성공 표본의 변화도 고려해야 한다. `d-a-001`은 v9에서 기대값이 강화돼 이전 자동 통과율과 직접 비교하지 않는다.

번역 프롬프트 `translate-v9`, 용어집, 번역 재시도 지시는 유지한다. 반복되는 선택 질문·혼합 문자 오답의 문장별 예외와 `N nights → N박` 힌트는 추가하지 않는다. 향후 학습 자료는 평가 문장과 분리해 작성·검수한다.

- 프랑스어 기능어와 대명사·동사 등 문장 근거를 이용해 확실한 미지원 원문을 번역 호출 전에 기존 확인 질문으로 돌린다. 영어·스페인어와 겹치는 단어, 등록된 고유명사, 짧거나 불확실한 문장만으로 프랑스어라고 확정하지 않는다. `Notre Dame du Lac` 지명과 `EST/ET` 약어가 들어간 영어의 오탐도 검사한다. 전부 대문자인 프랑스어는 약어와 구별하지 않는 보수적 한계가 있으며, 이 검사는 모든 미지원 언어를 탐지하는 언어 식별기는 아니다.
- `destination-v4`는 길 묻기와 장소 방문·볼거리 관람 희망도 목적지 요청으로 명시한다. 평가·학습 자료와 지문이 겹치지 않는 한국어 길 묻기, 스페인어 방문 희망 예시를 추가했다. 다른 목적지가 없는 취소·방문 부정, 과거 방문·사실 설명은 목적지 요청으로 취급하지 않도록 명시한다.
- `g-d-012`와 `ges-d-004`는 기존 검색기에 원문만 전달해도 각각 만장굴·성산일출봉 후보가 나온다. 모델이 `other`로 분류하면 검색 전에 반환되는 구조다. 실제 실패 응답이 없어 의도 분류가 원인이라고 확정하지 않았으며, 검색 점수·별칭이나 모델의 의도를 강제로 덮어쓰는 규칙은 바꾸지 않았다. 두 문장의 모델 성공 여부는 재실행에서 확인한다.

자동 통과는 의미·자연스러움 검수를 대신하지 않는다. `review.csv`의 사람 검수와 스페인어 원어민 확인, 시연 PC·백엔드 결정 및 앱 연동은 남아 있다.

로컬 검증: 전체 테스트 1,218건·주행 시나리오 통과(`run/verify-a2fb0d6012/report.json`), 문맥 예산 932건 통과(최대 2,696/4,096토큰). 개발 번역 입력의 사전 차단 비교에서는 `d-a-015`만 추가됐고 general·general_es·naturalness.dev의 정상 입력에는 새 차단이 없었다. 실제 모델 재평가는 수행하지 않았다.

## 번역 자연스러움 1단계

사용자 검토에서 다듬기는 개선과 악화가 비슷했고 보증금 수수 방향 등 의미 변경을 놓쳤으며, general p95가 337→1135ms로 증가했다. `POLISH_KO=0`을 유지하고 학습 초안 생성 안내도 다듬기를 끄도록 바꿨다. 다듬기 전 출력에서도 심각한 오역이 보고돼 기존 자동 통과율을 MVP 품질 도달 근거로 취급하지 않는다. 원본 전체 출력이 로컬에 없어 약 200건의 전수 의미 검수는 수행하지 않았다.
