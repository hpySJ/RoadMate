# 번역 자연스러움 개선 계획

현재 검토는 **AI 검토(참고)**다. 자동 검사 통과나 AI 간 동의는 의미 정확성·원어민 검수를 대신하지 않는다. POLISH_KO=0을 유지한다.

| 문제 유형 | 첫 대응 | 확인할 부작용 |
|---|---|---|
| 대명사·말투 | 기존 대명사 정규화, 선택 문체 규칙 | 동사 ‘나다/내다’, 인용, 발화자 관계 보존 |
| 직역·현장 표현 | 선택 현장 용어집과 독립 문체 예시 | 생략·추가·주고받는 방향 변경 |
| 낱말·용어 오역 | 문맥이 명확한 용어집 | 다의어를 한 뜻으로 고정하지 않기 |
| 검사기가 놓치는 뜻 오류 | 일반 패턴으로 검증 가능한 경우만 검사기 보강 | 오탐과 원문 의미 손실 |
| 일반 패턴으로 잡기 어려운 뜻 오류 | 문제 유형·출처 ID만 학습 후보 목록에 기록 | 평가 문장·AI 대안을 학습 자료로 옮기지 않기 |
| 외국어 섞임·문법 | 로마자 검사·재시도 지시, 문체 실험 | 허용된 지명·약어·단위 보존 |

검토가 끝날 때마다 아래 기록에 원본 run 경로와 해시, 독립 판정, 불일치, 최종 사용자 판단, 채택/보류 이유를 추가한다. 현재 실제 새 모델 출력에 대한 검토 결과는 없다.

| 날짜 | 근거 | 결정 | 다음 확인 |
|---|---|---|---|
| 2026-11-09 | 제공된 오류 보고와 로컬 회귀 검사 | 연료 ‘아닌’·장소 종류 검색 수정, 선택 실험 준비 | DLPC 실측과 독립 AI 검토 |

## 독립 실험

| 변수 | 기본값 | 변경 |
|---|---:|---|
| TWO_STEP_KO | 0 | 한국어 목표일 때 한 호출에서 literal 다음 translated_text 생성. 출력 예약 256→512 |
| NATURAL_STYLE_KO | 0 | 한국어 목표에만 짧은 문체 규칙과 독립 예시 6개 추가 |
| FIELD_GLOSSARY | 0 | 해당 어휘가 원문에 있을 때만 현장 용어 힌트 추가 |

검사·시각·대명사 정규화는 translated_text에만 적용한다. literal은 앱 응답에서 제거하고 LOG_REJECTED=1 로그에만 기록한다. literal의 의미를 정답으로 취급하지 않으며 최종 출력은 항상 원문과 비교한다. 두 단계는 지연과 오역 고착 가능성이 있는 실험이다. 로그에는 원문과 출력이 들어가므로 개발 평가 자료만 사용한다.

세 변수를 한꺼번에 켜면 효과 원인을 분리할 수 없다. 기본 스크립트는 문체·용어를 끄고 4B 기준/4B 두 단계/8B 기준을 비교한다. 문체·용어 실험은 같은 모델에서 각 변수만 바꿔 별도 평가한다. run.json과 summary.md에 실제 서버 설정 및 실행 중 일관성 검사를 남긴다.

새 예시는 pay for, over N minutes, pick up, passenger door, 공손한 부탁, 반납 전 물건 꺼내기 패턴이다. 새 예시는 평가 출력 대안에서 가져오지 않은 추론 전용 예시이며 training_allowed=false다. 현장 어휘에는 차량 수령/반납, 조수석/운전석, 연료 절반, 타이어 공기압 경고등, 주차 입장권/위반 고지서, 통행료가 포함된다. 기존 찌그러짐·긁힘·엔진 경고등 용어는 재사용한다. parking ticket 같은 다의어는 문맥 없이 주차권으로 고정하지 않는다.

## 채택 기준

동일한 원문 행에서 두 설정을 모두 판정한 결과를 비교한다. 전체 행 수, 양쪽 판정 완료 수, 미판정 수, 502·확인 질문 수를 함께 보고한다. 차이가 난 행만 고르거나 실패 출력을 품질 분모에서 숨긴 채 비교하지 않는다.

1. 같은 행의 ‘나쁨’ 비율이 감소한다. 품질과 뜻 오류는 한국어·영어·스페인어 및 방향별로도 확인한다.
2. FAIL·502·뜻 오류가 늘지 않는다. 숫자·연료·부정·좌우·언어·로마자 검사는 그대로 유지한다.
3. 동일 장비·입력·서버 조건에서 HTTP p95 증가가 300ms 이하다. 원래 model p50/p95도 함께 보관한다.
4. 실행별 변동이 의심되면 후보 설정만 반복 비교하고 사용자에게 불일치 행을 전달한다. AI 합의로 자동 채택하지 않는다.

## 자료 경계와 LoRA 후속 계획 — 실행하지 않음

Claude/Codex의 review_* 대안은 검토 근거다. 프롬프트·예시·용어·POI·학습 자료에 재사용하지 않는다. 선택 예시도 추론 전용이며 기존 학습 빌더는 선택 플래그를 켜지 않는다. 평가셋을 보고 만든 문장 변형도 학습 자료가 아니다.

후속 실험 후보는 [Qwen3-14B 공식 모델 카드](https://huggingface.co/Qwen/Qwen3-14B)의 Apache-2.0 모델을 선생 모델로 쓰는 것이다(2026-11-09 확인). 실제 생성 전에 정확한 revision·모델 해시·라이선스 파일·자료 출처를 기록한다. 모델 라이선스만으로 입력 자료의 권리나 출력 품질이 검증되는 것은 아니다.

계획은 독립 현장 상황 설계 → Qwen 선생 모델 자료 생성 → 숫자·연료·부정·좌우·언어·로마자 검사 → 번역투 참고 표지 → 독립 AI 검토 → 사용자/언어 검토 → 그룹 단위 분할 → 소규모 LoRA 비교 순서다. 원문·출력 모두 data_boundary로 평가·추론 예시 중복을 제외하고, 의미상 가까운 변형은 별도로 검토한다. test.locked*는 누출 자동 비교만 허용하며 튜닝·프롬프트 선택·모델 실행에 사용하지 않는다. 이번 작업에서는 생성·학습을 실행하지 않는다.
